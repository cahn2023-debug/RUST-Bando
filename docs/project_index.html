2. Luồng Database & Metadata

V2 Storage Engine (Event Sourcing)

Toàn bộ dữ liệu được đóng gói trong 1 file .pmp (SQLite). Logic ghi thông qua Actor để tránh lock.

graph LR UI[React UI] -- "Invoke(update_metadata)" --> DBNC[Debounce/Batch] DBNC -- "Tauri IPC" --> IPC[register_tauri_commands!] IPC -- "Facade modules" --> CMD[commands/modules/* -> v2/v2_bridge/gis/basemap handlers] CMD -- "Bounded Message (1024)" --> EB[EventBus Actor] EB -- "Sequential Write" --> SW[StorageWorker] SW -- "Commit (WAL Mode)" --> DB[(".pmp SQLite")] DB -- "Trigger" --> FTS[FTS5 Search Index] SW -- "Notify" --> PW[ProjectionWorker] PW -- "Update" --> RM[Read Models / UI State]
Quy trình Metadata:
  • Lưu trữ: Cột metadata_json (Type: JSON).
  • Chỉnh sửa: Dùng json_patch của SQLite để update atomic.
  • Hiệu năng Backend: Đã bật WAL mode, Synchronous=NORMAL, và tích hợp Rayon cho tính toán GIS song song.
  • Hiệu năng Frontend: Tối ưu Granular Selectors và Memoization cho Virtual Tree (Virtuoso).
  • Tìm kiếm: Tích hợp FTS5 Virtual Table hỗ trợ Search toàn văn.

⚠️ QUY TẮC CỨNG (STRICT PROTOCOL)

Mọi thay đổi mã nguồn hoặc tính năng mới **PHẢI** tuân thủ quy trình sau:

  1. Duyệt (Review): Mở file này (docs/project_index.html) để đối chiếu kiến trúc kỹ thuật hiện tại, đồng thời dùng docs/INDEX.md làm cổng điều hướng tài liệu đọc được.
  2. Code: Thực thi code theo đúng layer (Domain -> Implementation -> Command).
  3. Cập nhật (Sync): Ngay sau khi code chạy thành công, **PHẢI** cập nhật các thay đổi mới nhất vào file HTML này (Thư mục mới, Command mới, hoặc Lỗi mới phát sinh).

Việc không cập nhật SSOT này được coi là nợ kỹ thuật (Technical Debt) nghiêm trọng.
